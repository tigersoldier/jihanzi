# ADR 0007: SM-2 重复复习防重与快照污染修复

**日期**：2026-08-16
**状态**：已采纳
**决策者**：同步事故排查（20260816 导出数据）

---

## 背景

2026-08-16 用户报告：大量汉字的学习记录被重复计算多次，复习时间被异常延后
（个别字 nextReview 推到 2085 年、2126 年）。对导出数据逐条重放核对后确认三类错误：

1. **快照 ×3 污染**：旧版 `initialPull` 每次同步把 remoteOnly 日志全部重放到
   已增量物化的快照上，同一复习被应用约 3 次——repetitions 翻 3 倍、interval
   按 ease 指数放大（22→21362→36500 封顶）。旧版 `isSnapshotPolluted` 阈值
   （`interval > 36500` / `ease > 5` / 非法日期）只抓极端爆炸，封顶值 36500、
   中度 ease 3.4 的中度污染全部漏检，修复从未触发，污染快照持续流转。
2. **机械重复条目**：147+ 条复习以 dayKey+1、timestamp+24h 被复制一份
   （3~7 月为主），每条都再计入一次 SM-2。
3. **双设备语义重复**：两个客户端用分叉状态各自把同一批到期字/新字排进队列
   复习（08-02/08-03 同 30 字集合、08-04/08-05 两次 present_chars 弯察示压仪），
   合并重放时两条 round-1 都应用，interval 成倍放大。

另有一类**缺失应用**：旧版按墙钟时间戳过滤重放，把新条目漏掉（如"及"08-04 的
d 评级从未应用到快照），快照与日志不一致。

## 决策

### D1：未到期的 round-1 复习不计入 SM-2（日志保留）

任务队列只包含到期字（`isDueForReview`），"未到期"的 round-1 复习只可能来自
双设备分叉、历史机械重复或重复点击。`applyReview` 对 `current.nextReview >
entry.dayKey` 的条目返回 false——等同巩固轮语义：写日志（审计/统计），不更新
快照。所有重放路径（重放/导入/合并/修复）经 `applyEntry` 统一获得此语义。

### D2：逐字修复，不整库重建

早期 compaction 裁剪了 143 个字的历史日志，整库重建会丢失它们的进度。修复
粒度按字：重放首日 ≤ 快照首日（日志覆盖完整，含"快照缺失早期应用"的情形）
且与守卫重放不一致的字，用重放值替换；重放首日更晚的字（日志缺早期历史）
不可验证，保持原样。

### D3：快照增加 appliedThrough 日志水位

`Snapshot.appliedThrough` = 最后应用条目的 timestamp（保存时取 max，时钟回拨
不回退）。重放过滤改为 `e.timestamp > appliedThrough`，与墙钟解耦。旧版快照
无此字段时回退 timestamp 行为，其缺失本身作为"旧代码产物"标记：同步采纳时
触发逐字校验修复。

### D4：8a 兜底——不可验证的重污染字重置 interval=1

历史不完整、无法验证且 interval ≥ 3650 天（10 年，正常复习链不可能达到）
的字，重置 interval=1、ease=2.5，尽快重新进入复习队列，靠真实复习自然重建。

## 后果

**优点**：

- 单设备与多设备的所有重复路径（全量拉取重放、机械重复、双设备分叉、
  双击）都在 `applyEntry` 一处被防重，语义集中。
- 修复按字进行，安全：只动日志能证明的字，compaction 裁掉的进度不丢失。
- 修复可离线自愈、幂等、可在每次启动与每次采纳旧版快照时执行；
  带 appliedThrough 的新快照被其它修复版设备直接信任，避免每次合并全量重放。

**代价与权衡**：

- `sm2State.lastGrade` 只反映**计入**的复习；8 月真实重复习中更好的评级
  只留在日志（8c：统计页的"最近一次复习"改从日志取，展示口径不丢失）。
- 143 个历史不完整的字无法验证，其中 29 个重污染字只能重置重学（D4）。
- 时间戳乱序（设备时钟偏移）时，同一对重复复习可能保留"后一天"的那条——
  结果确定但取决于排序。
- 未到期防护依赖"任务队列只含到期字"这一领域约束；未来若加自由复习功能，
  需要给这类复习打区分标记。

**部署注意**：

- 混入旧版本设备时：修复版设备靠"采纳旧版快照前逐字校验 + 启动修复 + 云端
  快照污染覆盖"三层防线自保，但旧设备自身的 UI 无法远程修复——发布说明必须
  明确要求更新所有设备（PWA 刷新页面完成 SW 更新）。
- 8b（pushLogs 读-改-写并发覆盖）为已知风险，单独排期，不在本决策范围。
