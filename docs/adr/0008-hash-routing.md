# ADR 0008: UI 状态由 location.hash 路由承载

**日期**：2026-08-29
**状态**：已采纳

---

## 背景

应用的 UI 状态全部保存在 React 本地 `useState` 中：底部三个标签页
（学习进度 / 孩子 / 生字本）、设置页、学习进度的月份视图与某天详情、
生字本中查看的生字等。任何状态切换都不写浏览器历史记录，导致两个问题：

1. **手机上系统后退键失效**：用户从标签页进入生字详情、日期详情后，
   系统后退键直接退出应用，无法逐级返回。
2. **刷新回到初始页面**：刷新后 `useState` 全部重置，用户丢失当前
   标签页、查看中的生字、翻到的月份等上下文。

## 决策

**用 `location.hash` 承载全部"页面级" UI 状态，状态切换即 URL 导航。**
应用部署在 GitHub Pages（base `/jihanzi/`），没有服务端重写，因此
不使用 History API 路径路由（否则刷新 `#/…` 以外的深链接会 404）；
hash 路由天然兼容 GitHub Pages 与 PWA standalone 模式。

### URL 语法

```
#/progress                             学习进度（本月）
#/progress/2026-08                     学习进度，指定月份
#/progress/2026-08/2026-08-16          某天详情
#/progress/2026-08/2026-08-16/花       从某天详情查看生字
#/child                                孩子
#/wordbook                             生字本
#/wordbook/wb/<id>                     生字本，选中指定字本
#/wordbook/char/花                     生字本中查看生字
#/settings                             设置
```

汉字段百分号编码（`encodeURIComponent`），解析时 `decodeURIComponent`；
无法识别的路由回退到默认页（学习进度）。月份 / 日期格式不合法时回退到
可解析的最浅层级。

### 核心设计

- **`src/router.ts`**：纯函数——`Route` 联合类型、`parseHash` / `routeToHash`，
  组件与路由间无直接 DOM 依赖，可单测。
- **`src/hooks/useRoute.ts`**：`navigate(route, { replace? })` 与 `goBack(fallback)`，
  监听 `hashchange` 把 URL 同步为 React 状态。组件根据路由**派生**展示状态，
  不再各自持有 `useState`。
- **push vs replace**：
  - 打开子页面（标签页切换、日期详情、生字详情、设置）→ `push`，
    系统后退键可逐级返回。
  - 选择器类操作（月份翻页、切换生字本）→ `replace`，避免翻页刷爆
    历史记录——后退键从"翻第 5 个月"直接回到上一标签页，而不是走完
    全部翻页步骤。
- **显式"← 返回"按钮 = `goBack`**：有历史可退时走 `history.back()`，
    与系统后退键行为一致；无历史可退时（直接打开深链接、刷新后）
    回退到父页面并 `replace`，保证始终停留在应用内。

### 不入 URL 的状态

以下状态**刻意不**进 URL：

- **学习会话阶段（presenting / reviewing / …）**：每次评分都切换，
  入 URL 会刷爆历史记录。会话已由 localStorage 持久化（`useToday.ts`），
  刷新恢复不受影响，因此维持现状。
- **筛选（生字本全部/已学/未学）、创建表单开关**：临时性 UI 状态，
  无深链接价值。
- **选中孩子（`selectedChildId`）**：跨标签页共享的会话偏好，入 URL
  会造成各标签页 URL 互相携带、切换标签即改变孩子。

## 后果

### 收益

- 手机上系统后退键可逐级返回：生字详情 → 日期详情 → 月份视图 → 标签页。
- 刷新后停留在刷新前的页面，月份、生字、标签页上下文全部恢复。
- 页面可深链接 / 分享（如把某天的详情发给另一位家长）。
- 路由解析是纯函数，`parseHash` / `routeToHash` 有完整单测覆盖。

### 代价与权衡

- URL 变长、含编码后的汉字（`%E8%8A%B1`），手改 URL 不友好——但
  用户不直接编辑 URL，可接受。
- 月份翻页 / 字本切换用 `replace`，后退键不会逐月回退——这是有意为之，
  避免历史记录膨胀。
- 会话阶段仍依赖 localStorage 恢复，URL 与 localStorage 双轨并存；
  若未来需要"后退键退出会话"之类的行为，需重新评估会话状态入 URL。

## 备选方案

### 方案 B：History API 路径路由（`/jihanzi/progress`）

URL 更干净，但 GitHub Pages 对未知路径一律返回 404（仓库未配置
SPA 回退），刷新深链接直接白屏；PWA `start_url` / `scope` 也需随之
调整。仅在部署平台支持重写时才值得考虑。

### 方案 C：查询参数路由（`?tab=progress&char=花`）

可行且 gh-pages 兼容，但与 hash 相比：参数顺序敏感、语义靠 key 推断、
"某个值缺省"表达不直观。层级式状态（月份 → 日期 → 生字）用路径段
表达更自然，故选 hash。

### 方案 D：全部 UI 状态入 URL（含会话阶段、筛选、选中孩子）

统一"刷新即恢复"，但会话阶段每次评分都产生历史记录（一节课数十条），
后退键会逐张卡片回退，体验反而更差；筛选等临时状态入 URL 只会制造
噪音。按状态性质分轨（见"不入 URL 的状态"）是更合适的粒度。
